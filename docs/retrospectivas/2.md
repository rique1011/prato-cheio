## 1. O que decidimos nesta iteração

### Decisão 1 — Migrar de SQLite para PostgreSQL

A equipe decidiu utilizar PostgreSQL como banco de dados
do Prato Cheio.

A decisão busca oferecer maior capacidade de evolução,
integridade dos dados e suporte a operações concorrentes.

Essa decisão foi registrada no ADR 0001.

### Decisão 2 — Implementar a expiração de reservas sob demanda

A equipe decidiu que doações aceitas devem voltar a ficar
disponíveis quando o prazo de reserva de duas horas expirar,
desde que a validade do alimento permita.

A verificação foi implementada durante operações do sistema,
sem necessidade de um serviço periódico independente.

Essa decisão foi registrada no ADR 0002.

### Decisão 3 — Manter a arquitetura compatível com o escopo atual

A equipe optou por manter a arquitetura baseada em
Node.js, Express e PostgreSQL.

Tecnologias adicionais, como Redis, foram consideradas
apenas como possibilidades futuras e não foram implementadas.

O objetivo foi evitar complexidade desnecessária nesta etapa.

## 3. Dificuldades encontradas

Durante o desenvolvimento, a equipe precisou lidar com
desafios de integração e configuração.

Entre as dificuldades observadas, destacam-se:

- Ajustes necessários após a migração para PostgreSQL.
- Configuração das variáveis de ambiente do banco de testes.
- Adaptação de consultas SQL para PostgreSQL.
- Correção de erros encontrados durante a execução dos testes.
- Organização das contribuições individuais utilizando Git.
- Necessidade de manter a documentação coerente com o código.

Também houve dificuldades pontuais no envio de alterações
pelo terminal Git, sendo utilizado o GitHub Desktop
como alternativa para publicação de branches.

## 4. O que aprendemos

A atividade permitiu compreender melhor a relação
entre decisões arquiteturais e implementação prática.

Os principais aprendizados foram:

- A importância de utilizar testes automatizados.
- A necessidade de verificar transições de estado.
- O uso de consultas condicionais para preservar
  regras de negócio.
- As diferenças entre SQLite e PostgreSQL.
- O funcionamento de branches e Pull Requests.
- A importância da revisão de código em equipe.
- O papel dos ADRs no registro de decisões técnicas.
- A importância de documentar limitações reais do sistema.

## 9. Reflexão final

### Qual foi a decisão técnica mais importante desta evolução e como verificamos que ela funcionou?

Consideramos a migração de SQLite para PostgreSQL
uma das decisões técnicas mais importantes desta evolução,
pois ela alterou a camada de persistência utilizada
pelas funcionalidades do sistema.

A verificação dessa decisão foi planejada por meio de
testes automatizados que exercitam o cadastro, a listagem,
o aceite e a coleta de doações utilizando PostgreSQL.

Além disso, as funcionalidades foram organizadas para
respeitar as transições de estado das doações.

A confirmação definitiva do resultado depende da
execução bem-sucedida da suíte integrada de testes
na versão final da branch entrega-2.
